01

DECIDE

Why should meeting intelligence start from a local trust boundary?

The project starts from two product problems at once: meetings lose operational context after the call, and many assistants make cloud processing the default before the user has chosen that boundary.

Why ClosedRoom exists

Meetings create knowledge.
Most tools leave it fragmented.

Raw transcripts are useful, but they are rarely the final thing people need. The value lives in what was decided, who committed to what, what changed, and what still needs attention.

01

Context disappears

Decisions, risks and commitments get buried inside long transcripts, notes and chat history.

02

Meetings stay isolated

A transcript explains one call. It does not automatically show how a project changed across several meetings.

03

Cloud becomes the default boundary

Many meeting assistants require sensitive audio and transcript data to leave the machine before intelligence becomes useful.

ClosedRoom turns meetings into a local operational memory instead of another pile of transcripts.
What matters

Useful intelligence with
explicit boundaries.

01

Local-first control

Audio, transcripts, prompts, analysis outputs, diarization and visual artifacts stay on the Mac by default.

“The local machine is the default trust boundary.”
02

Intelligence over transcription

ClosedRoom is designed to surface actions, decisions, risks, minutes and project updates , not just text.

03

Human-reviewable attribution

Speaker clusters remain stable. Visual evidence can suggest names only when confidence rules are satisfied.

04

Fail-soft enrichment

Optional diarization or visual intelligence can fail without invalidating a usable transcript.

BUILD

Separate capture, enrichment and analysis into explicit layers.

ClosedRoom preserves the meeting first, then coordinates transcription, diarization, visual evidence, structured analysis and project memory behind a local application boundary.

The product idea

Capture first.
Build intelligence after.

ClosedRoom preserves the meeting locally, then adds ASR, speaker diarization, visual evidence, and structured analysis as separate layers.

Architecture

Local-first is a
system design choice.

The UI talks to one local FastAPI boundary. Recording, jobs, ASR, diarization, local model runtimes, persistence and diagnostics are coordinated behind that boundary.

Product surface

React/TypeScript runs in the browser or native WKWebView shell.

Local orchestration

FastAPI + AppServices coordinate recording, transcription, analysis, runtime and workspace state.

Replaceable execution

MLX/Nemotron, FluidAudio, Qwen3-VL and local-llm-server remain isolated behind explicit service boundaries.

04

MEASURE

Make the trust boundary observable before making stronger claims.

ClosedRoom's strongest current evidence is architectural and product-level: the default path keeps audio, transcripts, prompts, analysis outputs and project state on the Mac, while external providers remain explicit opt-in choices.

Privacy boundary

Local by default.
Cloud only when chosen.

Default local path

Audio, transcripts, diarization artifacts, visual observations, local prompts, analysis results and project state remain on the Mac.

MLX / Nemotron · FluidAudio · Qwen3-VL · local-llm-server

Explicit opt-in path

Speechmatics and Gemini sit outside the default trust boundary and are used only when the user intentionally selects those providers.

No hidden cloud dependency in the default workflow.
05

DECIDE AGAIN

Keep local as the default, not the ideology.

The current product decision follows directly from the tested boundary: local processing owns the default workflow; cloud providers remain available only when the user deliberately chooses the trade-off.

CURRENT DECISION

Local by default. Cloud only when chosen.

Audio, transcripts, diarization artifacts, visual observations, local prompts, analysis results and project state remain on the Mac in the default path. Speechmatics and Gemini sit outside that trust boundary and are used only when explicitly selected.

  • Default meeting artifacts stay on the Mac
  • Cloud providers remain explicit opt-in paths
  • Optional enrichment can fail without invalidating a usable transcript
