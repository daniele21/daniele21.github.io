# Project page rendered visual review protocol

This review is the manual evidence layer for the shared project-page UX contract.

## Routes

- `/android-local-llm-harness`
- `/local-llm-server`
- `/local-asr-server`
- `/closedroom`
- `/aura-finance`
- `/redact-guard`
- `/performance-lab`
- `/traffic-monitoring`
- `/traffic-monitoring-android`

## Required viewports

- 1440px desktop
- 768px tablet
- 390px mobile
- 320px minimum-width edge case

## Review questions

For every route and viewport verify:

1. The project purpose and outcome are understandable before technical detail.
2. `Overview → Decide → Build → Test → Measure → Decide again` remains visually legible.
3. The sticky subheader does not obscure headings or compete with the current phase.
4. No horizontal overflow is introduced by screenshots, code, tables, diagrams, or navigation.
5. Meaningful text remains readable and interactive targets remain at least 44px high.
6. Project-specific modules retain their identity instead of looking like generic template filler.
7. Evidence is clearly separated from open validation work; decorative graphics do not masquerade as measured results.
8. The page keeps one dominant reading path at mobile widths.
9. The final `Decide again` section states the current engineering consequence rather than a generic conclusion.
10. The next step is explicit and appropriate to the project maturity.

Automated capture produces full-page screenshots and structural diagnostics. Human inspection remains required for hierarchy, density, cropping, visual balance, and perceived clarity.
